# Amendment 1 to the Commonplace Monotonic Log 0.1-draft: BEAM-Native Recentering

**Date:** 2026-08-22
**Status:** In force (adopted by jes via `docs/proposals/2026-08-22-beam-native-revision.md`, committed byte-identical at `31188f6`)
**Amends:** `docs/commonplace-monotonic-log-spec.md` (0.1-draft, 2026-08-21). The original spec file is preserved byte-identical for provenance; this amendment states the deltas. A merged v0.2 text may follow at jes's direction.

## Normative changes

1. **Reference implementation.** The Elixir implementation (`commonplace_log/`) is normative for log semantics: entry validity (`Commonplace.Log.Entry`), canonical JSON (`Commonplace.Log.Jcs`), merge classification (`Commonplace.Log.MergePlan`), and synchronization (`Commonplace.Log.Sync`). The TypeScript Durable Object implementation (`worker/`) is reclassified as a conforming workalike, verified by the shared conformance corpus (`conformance/`) and black-box protocol equivalence — not by source-level lockstep. (Supersedes spec §14's framing of shared vectors as a twin obligation; the vectors remain a MUST for every implementation.)

2. **Physical storage layouts are adapter-specific.** Spec §12's DDL is no longer the universal representation of a log; it is the reference schema for the local one-file-per-log SQLite adapter (and remains in byte-fidelity with the workalike's schema). What is normative instead: the §8 invariants, the §9 operation semantics, and the persistence contract of proposal §6 (coherent read set; declarative commit plan; expected-revision atomic commit; acknowledgement only after durable commit). Adapters MAY use other layouts (e.g. the multi-log realm schema of proposal §7.2) provided the invariants and query semantics hold, immutability guards are retained, and the 1 MiB canonical-entry cap (§7.1) is enforced.

3. **Domain/storage error separation.** Persistence adapters return storage errors only (`stale_revision`, constraint violations, `storage_full`). Domain classifications (`writer_gap`, `writer_fork`, `entry_id_collision`, `invalid_entry`) originate exclusively in the normative Elixir engine. A storage boundary that emits domain classifications is non-conforming (proposal §14).

4. **Deployment model.** The primary Cloudflare deployment is a named realm Container running BEAM with its managing Durable Object as a durable SQLite sidecar; the default physical unit is one realm database holding many UUID-addressed logs. Per-log Durable Objects remain an optional sharding strategy and the basis of the lightweight workalike. Spec §13's topology describes the workalike deployment, not the primary one.

## Unchanged

The logical model (§5), identities (§6), entry format (§7, §7.1), invariants (§8), operation semantics (§9), synchronization (§10), wire protocol (§11) as the workalike's public surface, failure semantics (§15), security boundary (§16), and every §2 exclusion. Version 0.1's exclusions remain exclusions (proposal §3).
